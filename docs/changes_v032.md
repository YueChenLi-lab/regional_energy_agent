# v0.3.2：修改契约、比较口径与峰值研究

沿用既有单节点逐时模型、全年容量优化、NPV、离线重放与持久对话，不另建计算框架。普通页面刷新、预览、测试及CI不调用付费模型；本轮真实模型请求0次。

## 共用操作与单位语义

`edit_semantics.py`先识别完整数量/单位，再统一计算绝对目标、相对增减及明确基准比例；预算、负荷比例、年数、寿命、维护费、功率和排放上限共用同一规则。`modifications.py`把解析结果映射到允许的字段并核对保留项；模型提议仍须与本地授权完全一致。每项变更记录前后值、规范单位、原输入单位、操作类型及用户原句。

|输入（基准预算1000万元）|结果|
|---|---|
|预算增加到1200万元|绝对目标1200万元|
|预算增加200万元|相对增加200万元，结果1200万元|
|预算增加20%|基准乘1.2|
|预算提高到原来的120%|明确基准比例，乘1.2|
|预算提高到120%|未说明哪一基准，澄清|
|预算不要减少20% / 不要把预算减少20%|保留否定作用范围，不生成降预算契约，澄清|
|购电上限改为1000kWh / kW_th / kWfoo|单位维度不符，澄清；不能截成kW|
|排放上限改为100T / 100t / 100吨|统一为100000kg，物质继承已确认任务|

元/万元、年、kW/kWh、kW_th/kWh_th、按电/热量维护费单价完整匹配。明确CO2/CO2e后缀必须与当前任务相符；质量因子kgCO2e/kWh不能当排放总量。费率“增加20%”是相对增幅，“增加1个百分点”是绝对百分点增量；“改为2%”是最终费率。目标数值与“提高/降低”方向矛盾时先澄清。负值、多个选项、范围、不完整单位和不支持表达不猜测。

否定句在分句前保留整体范围，不能把“不要把”丢掉再解释为肯定修改。不确定的无标点混合否定也会澄清。明确“不要取消排放上限”可作为保留项。新解析仍是受控中文契约，不保证任意自然语言理解。

原持久对话的request_id、turn_id、edit_id、恢复、取消、修订与重选基准继续生效；回答不能无上下文成为新请求。输入未齐时不调用求解器；即使模拟模型强行提出修改，本地仍阻止执行。

## 统一可比性判断

`comparability.py`是报告、UI、对话及机器结果的唯一口径判断函数。检查时段/步长、完整年模式、电热服务与计量边界、电/热数组、排放物质、运行因子及来源范围条件、价格、规划年数/折现率/寿命/维护/更换/残值、设备成本/投资范围、COP/效率和PV资源。数组仅保存指纹，不塞入模型上下文。

- A：上述口径一致，预算/设备配置比较。
- B：经济假设敏感性，保留原始值与差值，但不称为同口径生命周期成本节省。
- C：数据/服务/排放/资源假设敏感性，不能把全部差值归因于设备配置改善。
- D：经济与其他输入同时变化，只展示带明确限定的原始差值。

结果在`changes.comparison_basis`保存每项核对、差异标签与中文摘要。没有旧基准证据的历史结果不推断为可直接比较。判断只核对已声明输入，不证明来源或研究假设已被工程核实。

## 峰值处理实验

```powershell
conda activate regional-energy
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
python -m energy_agent.cli peak-study --bundle examples/shanghai_2017 --spec configs/peak_sensitivity_v032.json --output outputs/my_peak_study --time-limit 120
python -m streamlit run app.py
```

云端使用`.venv/bin/python`；输出目录必须新建。不需要模型密钥或网络，完整Q与NASA原始缓存随代码提供；不重复周、不改年。三种输入由同一原值任务复制，仅改变声明点的电负荷；不根据处理后峰值重新设置容量上下限或购电上限。

预声明配置只列2017-01-13 00:00（4907.06kW）。线性情景使用相邻未列出区间；局部上限情景由原始前后24小时48个未列出点最大值819.48kW向上取整到100kW，得到900kW。两个跳变事件的两端并不是两个独立待替换峰值点。只处理列表中的一个点，未自动删异常或插补缺失。

每次输出包含：三份任务/标准化CSV/来源处理记录、处理前声明清单、固定条件、每组完整逐时结果/独立校验/报告，以及study.json、scenarios.csv、report.md。来源记录保存原文件SHA、标准化父文件SHA、处理方法、局部窗口/阈值、修改时点与前后值。原始文件在运行前后核对SHA。

本轮三组实际求解均optimal、间隙0，容量与初投一致。两种处理情景同时减少年电量和成本/排放；结论仅是当前预算/范围/参数下推荐未显示明显敏感，不判断真实峰值。实际证据见[v032_validation.md](v032_validation.md)及[v032_evidence/peak_report.md](v032_evidence/peak_report.md)。完整派生CSV和许可在[examples/peak_sensitivity_v032](../examples/peak_sensitivity_v032/README.md)。

UI先展示准备修改和保持条件、比较口径，再把JSON/工具轨迹放入折叠区。全年页可显式查看保存的三组峰值实验或上传study.json；读取不自动重算，也不调用模型。

## Windows与验证类型

CI矩阵新增windows-latest、Python3.12，启用当前进程UTF-8模式，显式清空模型配置。新子进程测试使用真实OS文件锁：一个进程持有请求锁，另一个相同请求在模型调用前被阻止；进程退出后新解释器恢复澄清并接续求解，重复回答返回原run_id。结果路径含中文和空格，JSON/CSV/Markdown实际读回。完整测试与离线重放也在Windows运行。

Windows CI、Streamlit AppTest与真实浏览器视觉验收是三件事。当前实际状态以v032_validation.md为准，不用Linux文件锁或AppTest替代未执行的Windows/浏览器测试。Conda本机可先设置`$env:PYTHONUTF8="1"`再运行测试（仅当前PowerShell进程），不修改系统全局编码。
