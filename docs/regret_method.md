# 多情景最小最大后悔决策 · v0.4.1

面向价格与资源不确定性的多情景最小后悔决策机制：在设备配置保持不变、逐时运行可适应的前提下，通过情景重算、可行性复核与后悔成本矩阵，识别有限候选中最大相对损失较小的配置，并提供可追溯的最坏情景解释。

最小后悔是成熟准则。本项目贡献是综合能源 Agent 中的受限编排、物理校验、状态处理和可解释交互，不宣称理论原创。参考阅读 <https://arxiv.org/abs/2005.10610>；不声称实现其具体模型。仅比较明确选定的有限候选、有限研究情景，不覆盖所有未来，不证明连续容量空间全局稳健最优。

## 两阶段定义

第一阶段固定 PV kW、电池 kW/kWh、热泵及锅炉 kW_th。候选只来自同一确认任务中已有候选或已校验求得的配置，记录来源 run_id 和五个容量字段的 SHA256。第二阶段针对每个配置、每个情景，调用现有求解器重新优化逐时运行；购电、弃光、充放电和供热分配可改变。不会将旧运行结果乘系数代替求解，也不会重新选择容量。

原任务必须有独立复核的可行见证。若没有，提示先完成评估或使用第一模块反事实修复；本工具不自动放宽任何约束。所有情景独立派生自相同原始任务，不连续叠乘。

设配置 k、情景 s 的有效成本为 C[k,s]。有限候选集情景基准 B[s] = min_k C[k,s]；后悔 R[k,s] = C[k,s] − B[s]；最坏后悔 W[k] = max_s R[k,s]。B[s] 使用该情景全部可行候选，包括在其他情景不可行的候选。仅在全部指定情景均有有效可行见证的配置中选取最小 W，保留并列。最大成本最小化是另一种准则，独立显示。没有情景概率，不报告“期望成本”。

手算单元测试 A=[100,160,220]、B=[120,130,180]、C=[150,140,160]，B[s]=[100,130,160]，W=[60,20,50]；基准最便宜 A，最小最大后悔 B，最小最大成本 C。此组数字仅是数学测试，不是能源实验。

## 授权及保持条件

`RegretScenario` 只接受购电价格、燃气价格、归一化PV及电负荷四种无量纲倍数，必须非负有限，工程保护范围0—10。默认基准/电价×1.2/气价×1.2/PV×0.8，均为人为研究假设，不是预测。电负荷另须 `allow_electric_load_change=true` 及字段白名单授权；不存在热负荷缩放入口。非法字段或单位拒绝，PV超过1拒绝而不裁剪。

所有情景保持热负荷、评估时段和步长、供能保障、预算、购电/排放/场地边界、设备参数与经济假设。原始文件不变；改变实测字段的派生数组标记为人为假设，不再冒充原值实测。记录父任务、每个修改字段的来源映射、原/新数组与完整输入指纹。任何负荷变化不触发容量上界或购电限值自动调整。

## 成本和原求解器复用

- 短期且无经济参数：C为评估期购电＋燃气购能费，投资另列且受原预算约束。不年化，不包含完整投资经济权衡，不称生命周期投资最优。
- 具备完整日历年和经济参数：C为同规划期NPV，含第0年投资、购能、固定/变动维护、更换与残值，沿用原代表年重复假设。将选定容量设成原容量求解器上下界相等，目标仍为NPV；不会用仅购能费调度再事后贴NPV标签。

固定绑定范围是算法约束，单独来源标记。用户原容量/储能时长范围留在结果和来源中，入口先检查候选确实满足原范围。安装、接入、寿命、更换等继续使用原经济实现；未修改 `capacity.py`、`optimization.py`、`economics.py` 或 `evaluation.py`。每单元再次独立检查电热平衡、设备/SOC/互斥/期末条件及原供能约束，核对实际返回容量和求解目标与最终比较费用（默认绝对容差0.0001元）。

运行排放按原 CO₂/CO₂e 因子与边界，不折现，不包含设备隐含排放。各情景相对于基准的比较沿用 `compare_basis`；价格、资源或负荷变化属于敏感性比较，差值不能统称设备改善。

## 状态与认证

| 单元证据 | 成本 | 处理 |
|---|---|---|
| optimal，gap=0，独立校验通过且容量固定 | 有效最优成本 | 可进入完整有限矩阵认证 |
| feasible_limit，或optimal但gap非零/缺失，独立校验通过 | 可行上界 | 只能形成近似排序 |
| 求解器确认infeasible | null | 该配置不能全情景推荐；不添加罚分 |
| no_solution_limit、error、rejected、校验失败、not_run | null | 不确定/部分结果；不能认证原全部候选 |

保留原始求解状态，不擅自把超时改成不可行。只要存在未知单元，完整推荐列表为空；可另列“仅已完成范围暂定项”。若一列无有效成本，整列后悔为null，不输出完整推荐。JSON不写NaN/Infinity；没有任意巨额罚分。容差内微小负后悔归零，超出则报错停止认证。并列按ID显示不代表严格优劣。

认证只针对当前模型/候选/情景及数值容差，不是工程可靠性认证。即使所有场景可行，有限矩阵也不能证明未知未来供能无风险。近似后悔是已得成本上界之间的差，并不是精确后悔上界或排序区间认证；本轮未实现上下界稳健排序。

## 受限工具与资源

`ToolRegistry.call('evaluate_minimax_regret', RegretRequest)` 两侧 schema 校验；独立表单和 CLI 入口，不改原对话状态机，不自动调用模型。两个示例问题仅引导填写表单，不代表任意自然语言理解。无密钥可运行。

请求绑定 baseline RunResult、run_id、版本、完整输入 SHA、候选来源/容量SHA、情景、成本口径、总时限、单次时限、调用限额、request_id。最多4×5单元，共享调用/时间预算；单次以剩余时间收紧。全年有经济参数必须显式确认。调用数指现有求解适配器调用，内部可能含LP与MILP；协作式时限不是进程级强制中止，模型组装、校验和写盘可有额外耗时。建议Community Cloud先短期小矩阵，全年显式线下执行。

跨进程文件锁；请求先落盘。相同ID与相同内容重放已保存完整回执，不调用求解器；同ID改参数拒绝；中断后无回执不自动重算，须使用新ID明确授权。单元缓存键包含完整原输入、容量和来源、情景、经济、目标及求解设置；当前仅重放整个已完成请求，不跨请求拼接缓存。单元未执行仍保留在矩阵，避免静默缩小推荐范围。

页面刷新、标签切换不计算；只有提交确认表单才调用。`ENERGY_AGENT_ENABLE_REGRET=0` 可关闭。结果不采用、不写回确认任务，本轮没有“采用配置”操作；未来若增加采用，必须在基准情景下显式重新核对，不能采用未来情景运行。

## 复现及下载

在项目根目录激活 Windows `conda activate regional-energy`；云端使用 `.venv/bin/python` 代替 `python`。依赖沿用 `requirements.txt`，未新增依赖。

```bash
python scripts/run_regret_cases.py --output outputs/my_regret
python scripts/run_regret_cases.py --output outputs/my_annual_regret --annual
python -m energy_agent.cli regret --request outputs/my_regret/synthetic_24h/request.json
python scripts/archive_regret_evidence.py --output docs/v041_evidence
python -m streamlit run competition_app.py
```

每次实验使用新空输出目录；CLI对已存在请求是离线重放。比赛页：优化结果→加载并评估一个案例→展开“多情景稳健决策”→选配置/情景与资源预算→确认保持条件→开始分析。成本/后悔热图、最坏后悔和结果说明都来自真实工具结果；JSON/CSV/Markdown可下载。详细JSON和来源在折叠区。

全年数据采用仓库已有 `examples/shanghai_2017` 离线包及其许可、校验与测点说明，不新增外部格式或声称新下载数据。归档及结果见 [证据说明](v041_evidence/README.md) 与 [验证记录](regret_validation.md)。
