# v0.1 计算模型与解释边界

本项目比较有限数量的设备容量配置，并对每个配置求解评估期内的运行计划。容量由候选配置给定，运行计划由 SciPy / HiGHS 计算。推荐结论必须使用“在本次评估的候选方案中”；不表示对全部容量连续空间找到了全局最优规划。

## 范围与口径

- 一个区域内的建筑常规电负荷和热负荷汇总到一个供能节点；满足每一个时间区间的电、热需求。
- 设备包括光伏、电池、电驱热泵、燃气锅炉和外部电网购电。热泵采用固定 COP，锅炉采用固定效率。
- 光伏可弃光，不允许向电网售电。电池只参与电力平衡。
- 不建模供冷、冷热管网、空间选址、故障备用、绿证、碳抵消和设备全生命周期隐含排放。收到这些尚未支持的需求时应显式提示，不能直接忽略。
- 仅统计评估期的运行阶段排放，不能据此声称全生命周期零碳。
- 示例为固定随机种子的 **合成演示数据**，包括价格、排放因子和设备成本等演示假设，不代表任何地区的现行价格、排放政策或工程报价。

## 时间与单位

输入时间戳对应区间起点，步长为 Δt 小时，各区间等长。电功率用 kW，热功率用 kW_th；电量用 kWh，热量用 kWh_th。燃气使用量统一为燃料低位热值（LHV）口径的 kWh。费用用元，排放用 kgCO2e。

若有 N 个时间区间，运行功率的下标为 t = 0, …, N−1。电池状态 E_t 有 N+1 个值：E_t 是区间 t 开始的储能，E_(t+1) 是本区间运行后的储能。功率乘以 Δt 才是该区间能量。

默认演示为 168 个一小时区间。接口和模型的 N 来自输入，允许其它时长和等间隔步长；未对完整年度大规模实例做性能验收。168 小时结果仅代表该评估期，不乘以 52 冒充全年结果。

## 候选与初始投资

默认候选族包括：A 电网＋锅炉、B 光伏＋电网＋锅炉、C 光伏＋热泵＋锅炉、D 光伏＋电池＋热泵＋锅炉。候选容量可配置，所有候选均为新建项目。锅炉在带热泵方案中提供补充供热，不构成经过故障场景检验的可靠性备用。

初始投资由设备容量、对应单位造价和安装成本假设计算；电池功率 kW 与能量 kWh 分开计价：

```text
设备购置费 = Σ（各设备容量 × 对应单位造价）
初始投资 = 设备购置费 × (1 + 安装费比例) + 电网接入费
```

安装比例和各设备成本来自任务参数，并随结果保留。电网接入费为各新建方案一致的给定费用。默认不计土地、融资、税费、拆除、残值、设备更换与全生命周期运维费用。模型没有据此计算全生命周期成本或净现值。

预算只约束初始投资，光伏容量受场地装机上限约束。超出这些限制的候选会被标记，不进入可行方案排名。评估期运行费和初始投资独立展示，不将一周运行费与全部投资相加称为全生命周期成本。

## 逐时运行约束

记 G_t 为购电功率，PV_t 为实际利用光伏，C_t / D_t 为电池充/放电功率，H_t 为热泵供热功率，B_t 为锅炉供热功率，L^e_t / L^h_t 为常规电/热需求。

电力平衡：

```text
G_t + PV_t + D_t = L^e_t + H_t / COP + C_t
```

热量平衡与燃气：

```text
H_t + B_t = L^h_t
燃气功率 F_t = B_t / η_boiler
燃气能量 = Σ F_t · Δt  （LHV kWh）
```

光伏可用功率 = 光伏装机 × 归一化单位出力；弃光功率 = 可用功率 − PV_t，二者均非负。购电、热泵和锅炉分别受购电上限、热泵热功率容量、锅炉热功率容量约束。没有隐含售电或负荷削减变量。

电池状态方程：

```text
E_(t+1) = E_t + η_charge · C_t · Δt − D_t · Δt / η_discharge
E_min ≤ E_t ≤ E_max
E_0 = 初始荷电比例 × 额定能量
E_N = E_0
```

初末状态相等，避免靠消耗初始储能获得虚假时段收益。充放电功率受额定功率约束。引入二进制状态 z_t：

```text
0 ≤ C_t ≤ P_battery · z_t
0 ≤ D_t ≤ P_battery · (1 − z_t)
z_t ∈ {0, 1}
```

这使带电池的运行问题成为混合整数线性规划，禁止同一时间区间同时充放电。电池效率在 (0, 1]，SOC 上下限及初始比例由参数校验；本版允许的固定 COP 为 [1, 10]。

## 目标与排放

```text
评估期运行费 = Σ [G_t · 电价_t + F_t · 燃气价格_t] · Δt
评估期排放   = Σ [G_t · 电网排放因子_t + F_t · 燃气排放因子_t] · Δt
```

运行目标为最小化评估期运行费；设置排放上限时，排放表达式另作为约束。设备隐含排放、售电收益、绿证和碳抵消均不在以上表达式内。默认不增加未声明的碳价或投资权重。

排名范围是通过预算、场地、逐时供能、设备运行及排放校验的候选，按评估期运行费升序。展示时同时保留投资与排放，让用户看到取舍。若求解只找到可行解而没有证明最优，推荐与排名中必须保留这一限定。

## 状态、无解与独立校验

求解前可确定的预算、场地和供热总容量不足等问题由预检查报告。求解器报告不可行时，只报告由预检查或求解器实际返回的结论；v0.1 不实施缺供诊断或不可行约束子集定位，不能猜测精确的不可行原因。排放约束下无解也不代表已求得最小可达排放。

默认没有缺供变量：无解即不满足本次评估的全部约束，没有通过隐藏负荷削减形成的“可行解”。若未来增加缺供诊断，应作为单独计算，输出缺供量，并标注“不满足供能约束”。

超时区分两种情况：没有可用解；已有待独立校验的可行解但尚未证明最优。记录求解耗时和求解器可提供的相对最优性间隙。无法获得间隙时留空，不伪装成 0。

独立校验从输出的逐时功率和 SOC 重新计算电、热平衡、容量边界、光伏利用及弃光、电池状态递推、初末状态、充放电互斥、投资、运行费和排放。只有满足数值容差内的全部约束，才进入可行候选比较。该校验独立于求解器的成功状态，避免把返回状态当成物理正确性的充分条件。

## Agent 与可追溯性

Agent 按“接收 → 输入校验 → 待补信息或准备运行 → 候选生成 → 求解 → 独立校验 → 比较 → 报告”编排独立工具。输入不完整时返回结构化待补项。所有工具输入输出经 schema 校验；自然语言模型仅将需求转换为允许的任务参数，不能执行任意 Python 或 shell，也不能替代数值计算。

无模型配置时，表单与预设任务可以完成全部演示流程；规则模式不支持任意自然语言理解。有模型配置时使用可替换适配器，解析失败仅有限重试。没有实际连接模型的验证不能表述为模型接入验收。

修改预算、需求规模或排放上限会创建新输入版本、重新运行并记录差异。每次运行保留 run_id、输入版本、来源记录、工具名称、状态、耗时与结果位置；不记录密钥或模型内部思维过程。


## v0.2电侧模式与资源估算

`electric_only`沿用同一电力平衡、二进制储能运行、周期SOC和独立校验，不另造成本/排放算法。热负荷零数组只作关闭供热的契约占位，所有热泵与锅炉容量必须为0。指标“满足”仅指所声明的电侧计量边界，不推断整栋建筑热/冷服务已满足。

G为既有电网，GB为新增储能，资源可用时增加GP和GPB。设备按实测峰值的可修改比例、10kW容量步幅及电池时长生成，原负荷不缩放；这是有限情景容量，非优化定容或已核实屋顶装机。仅计新增设备/功率变换和安装，既有用能设备与电网接入不计增量投资。G投资为0，因此预算为0仍应保留电网基线，不能沿用“所有方案均有新建投资”的解释。

NASA POWER请求UTC，按北京时间严格选择同期小时；小时标签为区间起点（官方FAQ Other Time Range），不使用LST。上海市级代表点不是匿名楼宇精确坐标，资源是卫星/再分析网格估计。中点太阳位置；Erbs（1982）由GHI分解DNI/DHI；isotropic模型计算倾斜面POA（albedo=0.2）；Faiman（2008）温度模型u0=25、u1=6.84；PVWatts V5（Dobos 2014，NREL/TP-6A20-62641）计算DC与逆变器AC，按1kW_DC归一。默认倾角20°、正南180°、系统损耗14%、温度系数-0.004/℃、逆变器额定效率0.96，均为情景假设，可修改。夜间中点太阳在地平线下时设模型出力0，逆变器模型限制输出；未校准遮挡、屋顶、积雪和微气候。

光伏是“气象驱动模型估算”，非楼宇实测。对该估算的验证包括单位、UTC对齐、物理边界、人工输入测试及真实NASA响应实际运行，不等同于电站实测校准。

价格、设备成本和排放因子仍可为人为假设，报告显示“实测与假设混合案例”。官方2022年上海电力因子0.5849 kgCO2/kWh已经核查，但不能冒充2017年因子或CO2e，故默认案例保留显式0.55 kgCO2e/kWh情景而未自动套用。因子按常数展开不代表实测逐时碳强度。不计基本电费、需量费或年度收费结算，168小时不外推年度。

## v0.3 扩展：全年、NPV和连续容量

以上为保留的v0.1/v0.2固定容量运行模型。当任务未提供economics时仍按该模式工作；此前“尚未实现更换/残值/NPV”的描述仅适用于旧模式。当前已实现完整日历年校验、逐年现金流经济评价、容量与逐时运行联合优化、有限ε约束成本—排放比较，详见[全年模型与经济口径](annual_planning.md)。容量模式保留全部原物理限制并独立检查；新模型不包含设备隐含排放或生命周期碳核算。旧168小时模式不自动年化。


## v0.3.1 受控参数更新

沿用上述容量与运行模型。新增项目额外年固定维护费，作为年度现金流与NPV目标常数`A(r,H)*额外年费`（A为折现年金因子），不改变初始投资预算或物理约束。设备比例固定维护费、变动维护、更换与残值的既有口径保留。电/热负荷可分别进行用户明确的研究情景缩放；保持供热时热数组、时段与足额服务不变，不能通过自动放宽约束制造可行性。详见conversation_v031.md。


## v0.3.2 比较与异常峰值边界

不改逐时物理模型、容量决策或NPV现金流。新增比较口径判断：预算/配置比较需核对时段、服务/负荷、排放及经济口径；改变经济假设或输入负荷时标注敏感性，不把原始差值称为同口径节省。详见changes_v032.md。

峰值实验从原值任务复制三份，仅对预先列出的Q电负荷点做插值/局部上限假设，固定容量范围、购电上限、预算、价格/因子/PV/热负荷及经济条件；不通过重设边界混入额外因素。原文件只读并核对哈希。负荷电量降低同时影响成本和排放，只评价本次推荐对处理假设是否敏感，不认定真实峰值或实测校准。
# v0.4 反事实上限搜索（新增编排，不改MILP）

反事实模块只改变用户允许的一个上限：初始投资预算、已设定运行排放上限或购电功率上限。原模型的负荷、逐时足额供能、SOC初末、容量边界与经济参数完全保持。使用现有求解状态和独立检查作为三值/失败可行性oracle；只有已知不可行/可行边界才二分，未知状态不能当成不可行。详见 [counterfactual_method.md](counterfactual_method.md)。以下原模型说明继续适用。

## v0.4.1 固定配置多情景运行与后悔

每个配置容量跨情景固定，分别重算运行；完整年度固定容量上下界后调用原NPV求解器，短期采用原购能费运行优化。情景只授权价格、PV及额外启用的电负荷倍数，供热及全部约束保持。当前候选集的每列最佳成本用于后悔；未知、限时可行和已确认不可行分开，不添加罚分。完整认证要求全部单元成本最优且gap=0并通过独立校验或已确认不可行；其他状态只近似或待定。详见[方法](regret_method.md)与[验证](regret_validation.md)。没有改写原MILP，没有隐含缺供，没有自动采用未来情景。
